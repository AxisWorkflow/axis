# Commands
> **Purpose:** Define how User invokes Commands and how Agents run them.

User can invoke a Command by typing `^<command> <optional additional text>` (e.g., `^help`) which matches to a command protocol file in `_Axis/Commands/`. Command files carry PLAIN names - `^help` runs `_Axis/Commands/help.md` - so the typed prefix is a documented convention, not part of any filename. The reserved `^^<command>` namespace routes supervision operations to [Practices > Supervision] rather than to one file per verb; this keeps the relational authority, discovery, and fallback rules together.

- A Command requires a `^` prefix followed by a valid `<command>` token, at the START of the message.
- A Supervision Command requires a `^^` prefix followed by one of the exact tokens in [Practices > Supervision > Dispatch]. A single-caret Command never aliases a double-caret Command, and `^^shutdown` is invalid - use `^^stop`.
- The `^` **prefix** is a strong but not deterministic signal for a Command. A caret elsewhere - math like `x^2`, or quoted control-notation like `^C` - is not a Command.
- The prefix is `^` (caret) because REPL hosts capture the obvious alternatives: Claude Code and Gemini CLI both intercept a leading `!` as shell input, and `/`, `@`, `:`, and `?` are claimed too - a `!command` never even reaches the Agent there.
- Command tokens are case-insensitive, a singular word (hyphens allowed), and no internal whitespace.
- Commands **can** be followed by whitespace and then additional text; in that case, the additional text is interpreted by the command for purposes related to the command.
- When you see a strong trigger in the form `^<command> <optional addition text>`, lazy-load and run the procedure in the associated file - no semantic interpretation needed. When the trigger begins `^^`, lazy-load [Practices > Supervision] and dispatch there instead.
- If no matching file exists in `_Axis/Commands/`, say so and list the available Commands (see `^help`) - never improvise or invent a procedure for an unknown token.
- Before Step 1 of every valid production Command, including `^^`, follow [Practices > Reminders > Surfacing and Session Checkpoint]: inspect open Reminder metadata against `reminder-check`, surface only newly due or newly created/rescheduled already-due Subjects, and advance the Flag only after trustworthy current UTC is established. The Command then continues normally. `^reminders` may fold this checkpoint into its own queue read. An empty queue is silent.
- Log one Event after running any Command that changes state. Exempt read-only Commands (`^help`, `^dashboard`); record-producing Commands (`^note`, `^idea`, `^log`); routine `^git` synchronization, whose commit is the audit entry; and the Git receive portion of `^resume`, which must not dirty the received checkpoint. `^resume` Logs only a separate material downgrade or approved correction under its owning protocol.
- Agents may run Commands from `_Axis/Commands/` subject to each Command's role gates. Supervision uses the separate authority matrix in [Practices > Supervision > Authority].
- A schedule (a cron job, a heartbeat) provisioned by User carries User's standing authorization for exactly the Command it names - but recognition still assigns the booted agent's role first: an agent serving as External refuses Mutating Commands regardless of provisioning, and a scheduled turn never satisfies a literal confirmation token - work that needs one fails toward a no-op plus a note. Repository or tree state is never an input to authorization.
- Development machines carry a `_Dev/` directory (excluded from production and every release). `^dev` enables Development Mode for the current conversation; the entry-point Development Mode fast path preserves it for that session and never invokes the normal Axis Workflow. Only while its `dev-mode` Flag matches the visible Development Session ID do `^benchmark`, `^compile`, `^eval`, `^pub`, and `^test` resolve to their plain-named files in `_Dev/Commands/` (`benchmark.md`, `compile.md`, `eval.md`, `pub.md`, `test.md` - exactly this list, one file per development command; a dev command added or retired without updating this sentence is drift). Those commands must abort when the Flag is absent or mismatched.

**Example:** The prompt `^note Publishing deadline is July 5, 2026` directs you to load and run `_Axis/Commands/note.md`; the command protocol will then save the associated text (`Publishing deadline is July 5, 2026`) into a new Note. Process new notes with contextual awareness, so in this case it might make sense to also enquire about adjusting the Plan, adding Tasks, and taking other actions to make the publishing deadline.
