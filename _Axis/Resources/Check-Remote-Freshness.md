# Check Remote Freshness
> **Purpose:** Offer one opt-in startup notice when the configured Git upstream contains incoming work.

1. Main Agent only, inside the admitted normal Session Start after User instructions load. Read [Settings > Remote Freshness]. Missing or `off` means no check and no notice; STOP. `on` is User's opt-in authority for this bounded fetch only. A standing instruction forbidding network access takes precedence; skip the fetch and queue one unverified notice, then STOP. External Agents, Subagents, fast-path turns and ordinary refreshes never run this Resource.
2. Require fresh `host-shell=yes`, `host-storage=atomic`, `Storage Policy=auto`, the same admitted `starting` identity, a live same-ID Main Marker and no foreign Main writer. A failed check makes only this enhancement unavailable; preserve canonical Axis operation and queue one concise unverified notice, then STOP. Never configure a tool, credential, remote or upstream as part of this check.
3. When Git, Python 3 and POSIX process-group timeout support are available, run the installed helper once with the project root and admitted Session ID, under a host timeout of fifteen seconds:

   `python3 -I -B _Axis/Resources/remote-freshness.py --project-root . --session {Session ID}`

   The helper has a total Git-operation budget of ten seconds. It fetches only the already configured upstream, without tags, submodules, prompts, FETCH_HEAD or automatic integration. Existing configured Git authentication may be used; none is installed or changed. No Python, missing Git, unsupported storage/repository, tool refusal or host timeout means remote freshness is unverified. Queue one short notice and continue the canonical file workflow; STOP. Do not replace the helper with an unbounded shell fetch.
4. Read the single JSON result as data. Queue its `notice` once with the greeting when non-null: incoming work recommends `^resume`; diverged histories require reviewed reconciliation; unknown/offline/authentication outcomes remain unverified. `disabled`, `already-checked`, `no-upstream`, `equal` and `local-ahead` are silent. Invalid output is unverified, never proof of synchronization. Do not display raw Git errors, URLs, credentials or paths. Never run `^resume` automatically or infer permission to merge, push or discard local work.
5. The ignored `_Temp/axis-remote-freshness/{Session ID}.json` receipt suppresses repeated fetches during this boot. A pending receipt means an interrupted check, not permission to retry; it leaves freshness unverified until User runs the normal synchronization command. Do not delete a receipt to obtain a more convenient result. It is regenerable session scratch, never a saved handoff or a distributed writer lease. The sending computer still needs `^save` and shutdown before the receiving computer uses `^resume`. STOP.
