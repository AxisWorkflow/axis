# Host Channels
> **Purpose:** Record, per host, what survives a compaction, which hook can mark it, and the Axis route that uses it.

`^install context hooks` reads this register; startup never does. Each host's own documentation decides; a row is only as current as its Checked date. No feature depends on a row: with the complete canonical entry available, its `After compaction` section and `turn.py` recover without hooks, and `_Axis/Resources/Context-Check.md` recovers without Python. Missing entry text requires the direct-read fallback below.

Columns:

- **Persistent channel** - what the host re-sends from disk after a compaction.
- **Compaction event** - the hook event that sees one.
- **After compaction** - whether a hook's output reaches the model then.
- **Route** - the `host-context.py install --host` value, or why there is none.
- **Status** - `compatible by design, unverified` until a live Axis probe is recorded, then `probed`; or `no route`.

Any other host (the Antigravity CLI, Grok Build, a raw API, a chat surface without files, or a host whose hooks were declined) has no row and no route: the entry file and `turn.py` carry recovery there.

- **Card and role text** go only to Claude Code and Codex, where a session's host ID can be bound to its Axis Session ID. Every other route marks and prints nothing, because none of those hosts adds a compaction hook's output to the model's context.
- **The startup core** (`_Axis/Resources/Starting-Context.md`) goes only to Codex, after the role-neutral line on `compact` through an entry installed with `--core`, never on `resume`, when it is whole, current and fits the 10,000-token limit; it is role-neutral, so a spawned agent that receives it gains no role. It stays in context, so each later request carries it until the next compaction.
- **The per-turn line** is not installed: the script answers Claude Code's `UserPromptSubmit` with it, but in the 3.18 live check sessions with that entry followed fewer planted rules before compaction, so `^install context hooks` leaves it out.
- **Marks from other hosts** carry an unbound session hash, so `turn.py` treats them like a mark without a session ID. Gemini CLI exposes `GEMINI_SESSION_ID` to hooks, which a later binding could use.
- **One mark per compaction.** On Cursor and Copilot CLI, `host-context.py` checks the project's Claude Code settings before marking; a host that runs both entries marks once.

## Entry imports

`AGENTS.md` is the complete entry source. `CLAUDE.md` and `GEMINI.md` contain only `@./AGENTS.md` plus a final newline. Imports resolve relative to their containing file. An unavailable import needs the portable fallback: ask the host to read and follow the ordinary project-root `AGENTS.md` directly. Do not substitute a link, parent search, absolute path or another discovery filename.

[Claude Code memory documentation](https://code.claude.com/docs/en/memory) describes relative imports and native import deduplication (documentation checked 9 Nov 2026). This does not establish import or deduplication behavior in Cowork, Grok Build, or every installed host version. A host that reads `AGENTS.md` itself, as the Antigravity CLI does, needs no import. Grok Build discovering both AGENTS and CLAUDE does not prove it expands imports. The hook observations in the table above are separate evidence.

The canonical entry's repeated-processing guard cannot stop a host inserting text before the model sees it. It suppresses only repeated startup processing with complete current context; turn checks and context recovery remain mandatory. No token saving is claimed.

## Hook lifecycle

Load this section only for context-hook installation, upgrade, removal or audit. Hooks remain optional and project-local; an Axis update does not install or activate them.

- Keep OpenCode at `.opencode/plugins/axis-context.js`. Its actual loader and live compaction event remain unverified. A Node import tests the plugin, not OpenCode's discovery or trust behavior. Do not move it to `.opencode/plugin/` without current official documentation and an offline probe of the installed loader supporting that change.
- Recognize a plugin only by its full bytes at an explicitly listed path. Use the published payload hashes retained in `host-context.py`. A matching header, filename or script reference does not establish ownership. Preserve a modified or unknown file and report it.
- Preview every change. Before replacing or removing a known plugin, the helper retains and reads back its exact bytes and a separate operation record in `_Temp/Context/hook-rollback/`, outside the host's plugin loader. The record binds the path, prior hash/mode or absence, backup, and expected postimage/mode or absence before mutation. Include its path in the installation Log. Preserve it until the change and any rollback are verified; it is recovery material, not disposable scratch.
- For rollback after failure or interruption, read the retained operation record and verify its backup hash. First require the plugin path to be absent after removal, or to equal the recorded postimage and mode after replacement. Preserve any other current file. Restore the retained preimage atomically at the same path and prior mode, through plain directories only, then verify the complete bytes and mode. If the prior file was absent, remove only the exact logged postimage and verify absence. A failed or unverified restore is not success.
- A release's `Retired Paths` may name an exact project-local plugin path and its shipped SHA-256 values. It never grants ownership of a folder or modified content. Preview the explicit removal or replacement separately from the ordinary Axis update; preserve the preimage and verify rollback as above. Do not scan for similarly named files or add a host folder to the updater's recursive managed set. A new path needs its own exact source evidence and tests.
- For audit, run `python3 _Axis/Resources/host-context.py audit`. It reads known project paths only and prints hashes and classifications, never settings or commands. `payload_releases` means the bytes match those releases; it does not prove which release installed them or that the host loaded them. Identify the installer release only from a verified installation Log whose path and postimage hash still match. Otherwise report it as unknown. A missing Python interpreter leaves this inventory unverified; compare those exact paths and published payloads by the host's read-only file tools instead.
