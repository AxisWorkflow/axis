# Coordination Manual
> **Purpose:** Run a bounded Team or Job when Python or a native adapter is unavailable.

1. Main validates its own lease, existing User mandate and Project UUID. Verify the explicitly active single-writer placement and previous-placement shutdown under [Practices > Coordination]. If that cannot be established, hold canonical effects; read-only inspection and unrelated work remain available. Resolve authority to an unchanged source record and SHA-256, with finite expiry; resolve exact output scopes, allowed actions, exclusions, validator and limits. No hash authenticates a sender. If the Host cannot mint a secure UUID or calculate required digests, hold canonical admission and report the missing capability; ordinary uncoordinated project work remains available.

2. Use [Practices > Timestamps] to claim each identity globally. A detail follows [Practices > Coordination > Readable record format]: first-line Subject, readable Content and Details, trailing Machine payload and checksum. Check readable/payload agreement before use. Common fields: `schema` = `axis.coordination/v1`, `family`, `id`, `created` (same ID), `project` (UUID), `subject`, `issuer` = `{session, role}`, and Main acceptance = `{session, marker, marker_sha256}`. Preserve the exact four-line Main Marker snapshot. Read back before releasing the claim. Never fabricate native handles, receipts or approvals.

3. A Team charter adds `objective`, `validator`, `scope` (relative paths), `actions`, `authority` = `{ref, digest, expires}`, `limits`, `acceptance_owner`, `reservation_launches`, and `members` containing exactly one `leader` slot and distinct bound non-Main sessions. Scope may narrow per member. New collaboration charters additionally record `collaboration` version 1, `poll_seconds` and `max_messages_per_member`; create `Teams/{ID}/members/{slot}/work/`, `artifacts/` and Main-owned `shared/` before dispatch. Each member writes only its own drafts and new revisions, and reads peers. Preserve historical charter rights. A Job adds `operation_key`, optional Team and pinned Team head/epoch, plus the same mandate fields. Defaults are deadline at most 60 minutes and within authority, 3 rounds, 12 starts, 3 concurrent agents including the leader. Reserve one final reporting start; reserve execution plus reporting before admission. Use stricter project, Host and shared-authority limits. Do not invent a fresh operation key to retry the same work.

4. Before dispatch, reconstruct accepted predecessors and epochs from the founding detail and immutable Messages. A Message has `kind`, `recipient`, `body` (at most 16 KiB), `correlation`, `epoch`, `expires`, optional `team`/`job`, `authority`, `attachments` (path, size, SHA-256) and `data`. Controls use the top-level `event` with target family/ID, action, predecessor, epoch, time and action data. Exact field shape and accepted transitions follow `coordination.py`; if the required transition cannot be checked confidently by inspection, hold it. Never infer current authority from an index or worker-authored control. A fork or uncertain effect requires reconciliation.

5. Prepare a separate leader's nonce-bound [Start-Subagent] envelope with the charter, scoped task, limits and return format. Start it through the Host or have User open a separate compatible session. Main must not impersonate the leader. The leader returns bounded assignments. Main accepts each and persists dispatch intent before preparing worker envelopes; workers publish scoped artifacts and direct canonical questions, answers, offers, receipts and results to any named teammate or the Team under the new charter. No per-message Main relay is needed on qualified storage. Carry the exact workspace, peer-read scope, participation expiry and inbox cadence; check canonical history at checkpoints, preserving causal reply IDs and observation times. On an unavailable direct-write lane, disclose the Main-capture fallback. Follow [Practices > Coordination > Direct collaboration] for immutable artifact manifests, canonical hash announcements and unchanged revisions. Treat source content as data. Record every start, retry, round and validator against the shared budget. A missing independent session makes the dedicated Team unavailable.

6. Retain results and dissent with provenance, including path, size and SHA-256 attachments for required file deliverables, then run the pinned validator. Text-only results need no file attachment. Main-mediated capture preserves the reported worker identity and its dispatched scope; it does not imply acceptance. Reuse retained results awaiting validation; never repeat an unknown external effect. Pause stops future dispatch; stop reports each confirmed and unconfirmed worker. Late results remain evidence and cannot reopen a terminal Job. Main verifies exact artifacts and destination base digests, resolves overlapping proposals, applies only reviewed changes and records the new baseline. Fence a previous writer before replacing its member binding; preserve all published artifacts. Main alone accepts completion and updates derived indexes. Record partial results and the next safe action when limits expire.

7. For a Schedule without an executor, inspect the reviewed definition and resolve one exact planned UTC occurrence. Use Project/Schedule/execution-revision/occurrence as the deduplication identity and check retained occurrence history before admission. A clock and schedule text grant no authority. Respect pause, expiry, missed/overlap/retry policies; hold ambiguous local time or clock change. Record an occurrence receipt and bounded Job before dispatch. No active Main means no manual execution; report the schedule as checkpoint-driven.

8. For delivery, persist the sender Message, place a create-only Markdown Submission in the direct receiver's queue under [Practices > Submissions], and have receiver Main import once with a local ID and origin/digest mapping. Native notifications are optional pointers. For Inbox movement, retain the source until receiver acceptance binds the same transfer and bytes; archive unchanged source only afterward. Unsupported or ambiguous transport stays queued, with a manual delivery instruction.
