# Boot Manual
> **Purpose:** Start an Axis Main session with shell commands only, when `boot.py` cannot run. Same records as `boot.py`; run each step from the project root.

Before admission or ordinary work, inspect `_Axis/Flags/merge-pending` and `_Axis/Merges/` under [Practices > Merging] (or run the installed `merge-project.py --root . status`). A retired source or source-side barrier stops startup; do not create a Marker there. An incomplete destination journal permits Main admission only for merge recovery before unrelated work. Malformed state holds; External Agents never perform that recovery.

Stop at any failed check, tell the user which step failed, and leave everything else unchanged.

1. **Session ID.** Run this command and keep what it prints as `{ID}`:

		TS=$(date -u +"%Y.%m.%d.%H.%M.%S.%3NZ"); case "$TS" in *3N*) TS=$(python3 -c 'import datetime as d;n=d.datetime.now(d.timezone.utc);print(n.strftime("%Y.%m.%d.%H.%M.%S.")+"%03dZ"%(n.microsecond//1000))' 2>/dev/null || node -e 'console.log(new Date().toISOString().replace(/[-T:]/g,"."))');; esac; echo "$TS"

	`ls _Axis/*/{ID}.md _Axis/Archive/*/{ID}.md 2>/dev/null` must print nothing; otherwise run it again. Name the two Logs in steps 6 and 8 the same way. The no-overwrite create in step 5 is the collision guard, so no other claim is needed here.
2. **No pending update.** `ls -A _Axis/Updates/` may list `.gitkeep`, `operation.lck`, a `.DS_Store` file left by macOS Finder, and finished transaction folders: a folder holding `consumed.json` (a compacted one also holds `compacted.json`), or holding both `rollback.json` and `released.json`, is history (`ls -A _Axis/Updates/{folder}/`). Any other entry, a folder without those receipts, or a symlink: stop and follow `_Axis/Resources/Entry-Protocol.md`. (Before 2.01 this step accepted only the first two names, so every project that had ever run `^update` was sent to the long protocol.)
3. **Claim.** `mkdir _Axis/Flags/starting.lock` (in `_Axis/Flags/`, not `_Temp/`; failure means another startup is running or was interrupted: stop and tell the user), then write `_Axis/Flags/starting.lock/OWNER` with a random token. `_Axis/Flags/starting` must be missing, blank or `cleared`; otherwise remove only your `OWNER` and lock and stop.
4. **One Main, checked under the claim.** If any `_Axis/Agents/*.md` starts with `Main: session`, is under 1 hour old and has no `.kill` sibling, another Main is live: remove your `OWNER` and lock, then follow `_Axis/Resources/Start-External.md` instead. Judge every older one without a `.kill` sibling under `_Axis/Resources/Claim-Session.md` > Takeover: active under 1 hour, join as External the same way; under the takeover limit, remove your `OWNER` and lock and ask the user; on "take over" start again from step 1 with that session taken over, otherwise join as External.
5. **Marker.** Create `_Axis/Agents/{ID}.md` without overwriting (`set -C`), exactly: `Main: session`, a blank line, `session: {ID}`, `host: {your host}`. Then write `_Axis/Flags/starting` as `{ID}` and the current UTC time on two lines. Then run the Takeover sweep: before removing a foreign Main, record an intent Log with exact old ID, recorded host, measured idle time and authorization basis under [Displaced-Session]; recheck its identity, bytes and mtime, remove only while still eligible, and record completion only after verified absence. Delete each Main Marker taken over in step 4, every other `_Axis/Agents/*.md` over 24 hours old (`find _Axis/Agents -name '*.md' -mmin +1440`) and every `.kill` over 1 hour old with its Marker; tell the user the count in one line with the greeting.
6. **Opening records.** Append `{now} - {ID} - Session start` to `_Axis/Tracking/{ID}.md`. Read installed `current-version` and append `{now} - {ID} - STATUS [session] Axis boot version: {version}` to your own Tracking. Write a new Log `_Axis/Logs/{new ID}.md`, where `{new ID}` comes from running the step 1 command again (never a bare `date +%3N`, which prints a literal `3N` on macOS): `Session Starting`, blank line, `by: Main Agent`, `session: {ID}`.
7. **Capabilities.** Write each Flag in `_Axis/Flags/` as the value then the current UTC time: `model` (your model id), `host-spawn` and `host-parallel` (`yes` if you can start sub-agents), `host-shell` (`yes`), `host-local-llm` (`yes` plus the URL `http://localhost:11434/v1` on a third line only if `curl -s --max-time 2 http://localhost:11434/v1/models` answers, else `no`), `host-cloud-sync` (`yes` if the path contains `CloudStorage`, `Dropbox`, `OneDrive` or `Google Drive`, else `no`), `host-storage` (`atomic` on an ordinary local disk, else `serialized`).
8. **Commit.** Write a second new Log, again named by running the step 1 command: `Session Started`, blank line, `by: Main Agent`, `session: {ID}`, `axis-version: {verified boot version}`. Write `_Axis/Flags/session-id` as `{ID}` and the current UTC time. Write `cleared` into `_Axis/Flags/starting`, delete the `OWNER` file you wrote, then `rmdir _Axis/Flags/starting.lock`.
9. **Banner.** Show the Ready banner from `_Axis/Resources/Lifecycle-Presentation.md` > Main startup (Version from `_Axis/CHANGELOG.md`, Context from the effective Context Management Setting, Project from `_Axis/PROJECT.md` line 1, this folder, `{ID}`) and greet the user in one line after one blank line, introducing yourself as Axel, the Main Agent.
10. **Pending before any answer.** Before queue inspection, also create a missing plain `_Axis/Merges/` with `.gitkeep`, preserving all existing merge state and holding spelling/link collisions. Then create only missing `_Axis/Submissions/`, `_Axis/Messages/`, `_Axis/Teams/`, `_Axis/Jobs/`, `_Axis/Schedules/` as plain directories with empty `.gitkeep` files. Create missing `_Axis/MESSAGES.md`, `_Axis/TEAMS.md`, `_Axis/JOBS.md`, `_Axis/SCHEDULES.md` only for empty families, using the standard cached-state header, `pending-count: 0`, `verified: never` and empty ID/Subject/State/Head table. Submissions has no summary. Check every destination first; links, spelling collisions or a missing index beside populated records require canonical repair, never overwrite or claim a zero queue. Preserve all existing bytes; do not initialize placement, import, execute or retire Requests by creating this layout. Log actual additions. Review/import bounded `_Axis/Submissions/` entries once under `_Axis/Practices/Submissions.md`, then adjudicate pending Messages under `_Axis/Practices/Messages.md`; legacy Requests are held for explicit migration. Never rewrite old Messages or scan all history as an active queue. If `_Axis/PROJECT.md` declares a project overlay, validate and activate it with `_Axis/Resources/Load-Project-Overlay.md` before applying it. If `_Axis/Flags/project-ready` does not hold a timestamp, say "Your project needs to be set up." and follow `_Axis/Resources/Start-Project.md`. If the project root holds a plain folder named exactly `Wiki` and no `_Wiki` exists, move it with `mv Wiki _Wiki` (since 2.05 the Wiki lives in `_Wiki/`), change each path to the root `Wiki/` folder to `_Wiki/` in `_Axis/Wiki/Input-Index.md` and `_Axis/Wiki/Library-Index.md`, tell the user in one line and Log `Wiki moved to _Wiki/`; if both exist, ask the user to move what they need from `Wiki/` into `_Wiki/`. Then, if `_Inbox/` is missing, create it with an empty `.gitkeep`. If `_Wiki/Inbox` is a plain folder and no `_Wiki/_Inbox` exists, run `mv _Wiki/Inbox _Wiki/_Inbox` and change each `_Wiki/Inbox/` path to `_Wiki/_Inbox/` in `_Axis/Wiki/Input-Index.md`; if both exist, ask the user to merge them. Tell the user in one line and Log `Inbox folders set up`. If `_Inbox/` holds items, file them under `_Axis/Practices/Inbox.md`. First Boot, only while `_Axis/Flags/project-ready` holds no timestamp: move each file under `.github/` that contains `axis:production-only` into `_Trash/` as `{yyyy-mm-dd}--{name}`, remove folders it leaves empty, tell the user in one line and Log `First Boot: repository-only files removed`. If `_Memos/` is missing, create it with an empty `.gitkeep`; move each report in `_Axis/Reviews/` and `_Axis/Status/` unchanged into `_Memos/Archive/` as `YYYY-MM-DD - Review - {topic}.md` (its local date and Line-1 topic), remove the emptied folders, tell the user in one line and Log `Memos folder set up`. Read the replies in any `waiting on you` memo edited after its Updated time under `_Axis/Practices/Memos.md`.
11. **Reading before any answer other than the greeting or a requested exact reply.** Read `_Axis/Resources/Load-Starting-Context.md` (core rules), `_Axis/INSTRUCTIONS.md`, `_Axis/MINDSET.md`, `_Axis/DIRECTIVES.md`, `_Axis/PLAN.md`, `_Axis/TASKS.md`, the newest Snapshots and the Notes index; then complete `_Axis/Resources/Start-Session.md` Step 2 items 5-6, 10 and 14-20 (environment binding, Mindset stamp, queues, index check, Notes overflow, Trash, Messages, remote freshness) and Step 5 (parent Project).

## Migration and update checkpoints

Before moving a Review or Status report to its descriptive archived memo name, retain a `Reference move` Log under [Practices > LinkMaintenance > Project boundaries and recorded moves]; preserve its exact source identity, destination and SHA-256, then verify unchanged moved bytes. This alias keeps old citations resolvable. Without the helper, record the same structured receipt manually under ordinary Main record guards. After adopted updates and startup migrations, complete [Practices > GIT > Update checkpoints] before ordinary work; report unavailable or blocked checkpoints explicitly, including delegated updates.

### Pending communication classification

When inspecting Messages, distinguish the global pending-history count from actual Main-recipient obligations. Validate recipients, dispositions and referenced Team/Job lifecycle under [Practices > Messages]. Retain uncertain routing for review and peer history unchanged; a global count alone does not require Main to answer every peer exchange. Derived counts are cached prompts, not authority.

New recovery layout: inspect exact `_Axis/Updates/{ID}/recovery.json` and `_Axis/Merges/{ID}/recovery.json` pointers as data before deciding a transaction is absent. Resolve only the declared `_Temp/Update-{ID}` or `_Temp/Merge-{ID}` ordinary directory. Update completion requires the checked completed receipt; merge completion requires a fresh-startup validated receipt. Before ordinary context, resume any closed-but-unretired update via its independently authorized frozen engine and validate completed merge contents using its plan-authorized frozen engine. Retire only after those checks. Missing pending recovery or malformed/contradictory metadata stops startup. Preserve legacy consumed/compacted journals and their original verification rules.
