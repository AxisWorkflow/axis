# ^refresh
> **Purpose:** Refresh the project - sweep stale state, resync records, and realign Plan with Tasks.

1. Sweep the project tree for stale `*.lock/` directories by following [Lock-File > Stale-Lock Sweep]: re-read `mtime`, atomically rename each stale candidate, and delete only the renamed directory. Never directly delete the active lock name. If deletion is blocked, follow [Rules > HostAndMeta > Deletion Fallback]. In the same pass, sweep stale `*.tsclaim/` claims in `_Temp/` (`mtime` over 10 seconds - see [Practices > Timestamps]), and sweep `_Trash/` per [Practices > Trash]: delete everything except `.gitkeep`, recreate `.gitkeep` if absent, and list what was removed in the final report; if the host blocks the deletion, count the contents and remind User to empty `_Trash/`. In the same pass, sweep `_Axis/Tracking/`: delete tracking files older than 7 days (telemetry, not evidence - no per-item approval; see [Practices > Tracking]), recreate `.gitkeep` if absent, and note the count in the final report. Also delete stale `.kill` tombstones in `_Axis/Agents/` (`mtime` over 1 hour) silently - see [Practices > Markers > The Lease].

2. Check `_Axis/Agents/` for Markers older than 1 hour: warn User and offer to delete each (see [Practices > Markers]). In the same pass, offer to delete any Marker that has a `{ID}.kill` sibling REGARDLESS of age - that session is already stopped, and on a delete-blocked surface the killer could not remove it, so it lingers reading as live. Delete the Marker and leave the tombstone to age out on its own schedule.

3. Apply bounded active-record overflow. If Notes exceed [Settings > Max Notes], archive the oldest excess per [Practices > Archiving > Automatic Note Overflow] (renew any old-but-still-important Note first). If `_Axis/Supervision/` contains more than 30 records, move the oldest excess unchanged under [Practices > Archiving > Automatic Supervision Overflow] until 30 remain. Report both counts separately.

4. Clear `_Temp/` - never silently: list every file you propose to delete and why it is regenerable, then delete ONLY what User confirms. Anything User might ever ask for again belongs in a Project Subfolder - offer to move it instead of deleting.

5. Repair malformed record names. Scan the twelve Index-Detail directories (`_Axis/Agents/`, `_Axis/Audit/`, `_Axis/CX/`, `_Axis/Followups/`, `_Axis/Ideas/`, `_Axis/Logs/`, `_Axis/Notes/`, `_Axis/Reminders/`, `_Axis/Snapshots/`, `_Axis/Status/`, `_Axis/Supervision/`, `_Axis/Tasks/`) for any file whose name is not exactly `{yyyy.mm.dd.hh.mm.ss.xxxZ}.md` (ignore `.gitkeep` and non-record temporary siblings). Do this BEFORE the sync check below - malformed names produce spurious mismatches there. Renaming a record to the convention repairs its identity; it does not edit its content, so it does not violate WORM.
	- a. Derive the corrected name from what the old one already carries, never by inventing a time: seconds present but no milliseconds or `Z` (`...ss.md`) takes `.000Z`; milliseconds present but no `Z` (`...ss.xxx.md`) takes `Z`; another date format that still carries a full date and time is rewritten into the Axis form; a name carrying no recoverable time at all falls back to the file's `mtime`. If even that is unusable, ask User rather than guessing.
	- b. If the corrected name already exists, increment the milliseconds and retry, per [Rules > Timestamps].
	- c. Skip live Markers. A `Main: session` Marker in `_Axis/Agents/` with `mtime` under 1 hour and NO `.kill` sibling is named with its Session ID and cross-referenced by `_Axis/Flags/session-id` - renaming it breaks session identity. A malformed Marker that is already stale gets deleted by step 2 instead and is never archived.
	- d. Present the full list first - old name, new name, and which rule produced it - and rename ONLY what User approves. Where the project uses git, rename with `git mv` so history follows the file.
	- e. Relink the mutable indices: update the `[Details...]` link in `_Axis/TASKS.md` or `_Axis/SNAPSHOTS.md` for every record you rename. Do NOT rewrite paths inside Logs, Snapshots, CX, Audit, or Status reports - those are WORM, and a stale path in an old record is history, not a defect. Record the old-to-new mapping in the Event you log for this refresh so the trail explains itself.
	- f. Repair duplicate identifiers the same way: when one timestamp names two records across the twelve directories and `_Axis/Archive/` combined (Subprojects excluded), keep the older or index-linked record under the contested name and rename the other by incrementing its milliseconds to the first free value per [Practices > Timestamps]. Present the list, rename only what User approves, and relink per item e. Renaming repairs identity, not content, so it does not violate WORM.
	- g. After approved repairs, re-run [Practices > Archiving > Automatic Supervision Overflow] if newly valid Supervision filenames leave more than 30 active records.

6. Verify `_Axis/TASKS.md` ↔ live or archived Task details and `_Axis/SNAPSHOTS.md` ↔ live or archived Snapshot details are in sync (ignore entries in template form); report any mismatch. An indexed record has exactly one detail path, live or under `_Axis/Archive/`, never both.

7. Validate Follow-Ups under [Practices > Followups]. Finish a crash-left move only when a live record is already validly terminal: move it unchanged to `_Axis/Archive/Followups/`, verify, and report it. Never invent an answer, outcome, or resolution reference. Surface malformed records, dangling `blocks:` targets, duplicate open asks, and open records found in Archive. Do not auto-correct their meaning; recommend `^followups` for User-directed resolution.

8. Validate Reminders under [Practices > Reminders]. Finish a crash-left archive only when a live record is already validly terminal. Close an open Reminder only when its exact target is deterministically terminal; update a target only when one unique archive path matches its timestamp identity. Surface malformed fields, duplicate intent, dangling or ambiguous targets, untrusted time, and open records in Archive. Never invent an outcome or time; recommend `^reminders` for semantic decisions.

9. Validate `_Axis/ENVIRONMENT.md` mechanically under [Practices > Portability > Infrastructure Inventory]: exact columns, Kind/Need domains, fixed non-executable Safe Revalidation token, safe fallback/reference, and no current-health or secret/host-binding data. Do not probe infrastructure, read Secrets, or mutate declarations here. Surface malformed or missing declarations and bounded undeclared-signal counts; propose exact rows but apply them only with User approval.

10. Realign Plan and Tasks - they drift apart silently, and nothing else checks. Skip quietly if `_Axis/PLAN.md` is still in template form (contains `{{`). Otherwise compare the `## Execution Path` stages against Active and Blocked Tasks and report three things: stages carrying no Task, Tasks that map to no stage, and stages whose work is finished while their Tasks stay open. Propose one specific fix per finding (a Task to add, a Task to cancel, a stage to close) and apply only what User approves; recommend `^plan` when the Plan itself no longer describes the work.

11. Refresh the Mindset. Compare the provenance stamp at the end of `_Axis/MINDSET.md` to the Mindset Settings in `_Axis/SETTINGS.md`; on any mismatch, or a missing stamp, regenerate per [Draft-Mindset] and tell User which Settings moved.

12. Surface stale work from each Task's durable `updated:` field, never detail-file `mtime`. Flag Active Tasks older than 7 days, Blocked Tasks carrying no stated reason or blocked more than 14 days, and `updated: Unknown` for review. For a Blocked Task awaiting a specific User action, create or reuse a Follow-Up only after User confirms the ask. Ask User whether each is still live, then update (advancing `updated:`), cancel, or leave it per their answer.

13. Refresh the Wiki, only if the Wiki is in use. Diff `_Axis/Wiki/Input-Index.md` against a live listing of `Wiki/Inbox/` and report any source that has never been ingested (recommend `^wiki`). Then run the quick health check per [Practices > Wiki > Review], or suggest `^wiki lint` for the full pass.

14. Surface what is overdue - recommend, do not run: an active Note older than 30 days (`^notes`); Ideas never reviewed or last reviewed over 30 days ago (`^ideas`); an overdue open Follow-Up (`^followups`); a due or unhealthy Reminder (`^reminders`); no Status Report in the last 7 days (`^status`); no Snapshot in the last 48 hours (`^save`); `_Axis/PROJECT.md` still carrying `{{` placeholders, meaning setup never finished.

15. Report what was swept, deleted, archived, regenerated, realigned, and flagged, then Log one Event for the refresh (include any old-to-new filename mapping from item 5). STOP.
