# ^save
> **Purpose:** Sync workflow and save a Snapshot.

1. **Check for Subagents.** Follow [Start-Subagent > How to Track Subagents] to check whether Subagents are running (Markers with a `Subagent:` Subject - `Main: session` Markers do not block). If Yes: warn User and STOP unless explicitly told to continue. Refresh your own `Main: session` Marker and `_Axis/Flags/session-id` while here: update the Flag's Line 2 timestamp; Line 1 never changes.

2. **Preflight Git receive.** Read `host-shell` under [Practices > Flags > Reading Flags]. When it is valid `yes` and an exact-root repository with upstream exists, read [Practices > GIT] and run the outgoing mode's early fetch/classification before changing save state. Integrate incoming work under its Take one action (a fast-forward, or a merge when the two sides changed different files) through Incoming Change Validation; if Workflow machinery changed, shut down for a fresh session and do not save under stale instructions. When a file changed on both sides, remember that this save can finish only as a local checkpoint. No repository, no remote, unavailable Git/authentication, or `host-shell` not valid `yes` never blocks the local Snapshot.

3. **Clear Temp scratch.** List your own scratch files in `_Temp/` and confirm deletions with User (if blocked, follow [Rules > HostAndMeta > Deletion Fallback]). Anything User may still want belongs in a Project Subfolder - offer to move it. Never silently delete a User-managed working file.

4. **Archive Note overflow.** If Notes exceed [Settings > Max Notes], retain the most recent active Notes and move the oldest excess under [Practices > Archiving > Automatic Note Overflow].

5. **Update Mindset.** If the provenance stamp at the end of `_Axis/MINDSET.md` no longer matches the Mindset Settings in `_Axis/SETTINGS.md` (or the stamp is missing), run `_Axis/Resources/Draft-Mindset.md` to regenerate it.

6. **Assess portability.** Read and follow [Practices > Portability > Always-On Save Assessment] end to end. Run every safe, locally observable check; validate every `_Axis/ENVIRONMENT.md` declaration; run bounded discovery and anomaly-only path scans. Never read Secrets content or list secret names, contact/authenticate to a remote merely to improve an infrastructure status, mutate an unrelated external system, enumerate global host state, or enter a nested Subproject. Keep the Archive Location portable ([Practices > Archiving > Archive Location]). Classify `Ready`, `Degraded`, or `Unverified`. An unavailable optional observation does not block the save.

7. **Seal configured Secrets.** When an exact-root repository exists and encrypted Secrets transport is configured, follow [Practices > GIT > Encrypted Secrets Transport > Send automatically] before writing the Snapshot. A successful seal becomes part of this checkpoint. Missing tool/identity, malformed state, or a conflict preserves plaintext and the last valid capsule, prevents any claim that current Secrets were transferred, and contributes a concrete portability finding. When plaintext credential material exists but transport is disabled, record it only as an omitted category.

8. **Save one Snapshot.** First synchronize the relevant Initiative section and its Plan/Task links under [Practices > Initiatives] when the current work uses one; include its key, phase, and next decision in the Snapshot without duplicating all its details. Follow [Practices > Snapshots] to save exactly one ordinary Snapshot carrying the exact `## Continuity` block from [Practices > Portability]. Include current Active/Blocked Task, open Follow-Up, and open Reminder IDs. Scale narrative length to Budget; the portability assessment remains complete at every Budget.

9. **Refresh the Project README.** When `project-ready` is valid, follow `_Axis/Resources/Refresh-Project-README.md` once. This updates only its bounded public-safe summary block; failure does not invalidate the Snapshot, but it must be reported and must not be called refreshed.

10. **Log the checkpoint.** Log one Event recording the project-root-relative Snapshot path, portability result, infrastructure result, encrypted Secrets state, Project README refresh result, what was archived/cleared, and whether a commit/remote send will be attempted. The Event is part of the checkpoint and must be written before the repository commit.

11. **Commit and send when configured.** For an exact-root repository, follow [Practices > GIT > Checkpoints] and the outgoing Shared Synchronization State Machine. Stage the whole eligible state, validate it and run the two record checks below, and commit the Snapshot and its Event together, along with the current capsule and refreshed Project README, as `axis: snapshot {timestamp}`. Re-fetch immediately before pushing. Push automatically only when the configured upstream remains strictly behind the local linear history. A commit/push failure or divergence leaves a truthful local checkpoint and must never be reported as transferred. With no remote, commit locally; with no repository, skip Git quietly.
	- **Record names.** Run `python3 _Axis/Resources/record-check.py names`. Without Python (or on exit 2), list the record folders (`_Axis/Agents/` aside) and in-project `_Axis/Archive/` families: a name other than exactly `yyyy.mm.dd.hh.mm.ss.xxxZ.md` (`.gitkeep` aside) refuses the commit; report a `.000Z` name absent from `git ls-tree -r --name-only HEAD`. `^refresh` repairs names.
	- **Write-once files.** Run `python3 _Axis/Resources/record-check.py write-once`. Without Python (or on exit 2), read `git diff --cached --name-status -M`: an `M`, or a rename below `R100`, on a Log, Snapshot, CX, Audit, Review or Supervision record, an `_Axis/Updates/` or `_Axis/Archive/` file, or a Task, Follow-Up or Reminder terminal at `HEAD` refuses the commit, unless an update transaction whose evidence this commit adds names the path.
	- On a refusal, do not commit: report the paths and rules (never contents) and Git as `needs reconciliation`, and ask User how to proceed.

12. **Report.** Identify the Snapshot only by timestamp ID or project-root-relative `_Axis/Snapshots/{ID}.md` path - never an absolute, home-relative, or drive-prefixed path. Report `Portability: Ready` as one healthy line; for `Degraded` or `Unverified`, name only new/material findings, infrastructure to re-establish, and unchanged finding count. Report Git as `synchronized`, `local only`, `remote not verified`, or `needs reconciliation`, plus encrypted Secrets as `current`, `omitted`, `unavailable`, or `conflicted` when relevant. Never expose a secret name/value, account, local path, or host job ID. After a successful remote send, add: `Use ^shutdown before opening this project on another computer.`

13. **Honor explicit handoff language.** If the additional text explicitly asks to shut down, stop, hand off, transfer writer responsibility, or save for another computer, run `^shutdown` after the save. For a Git handoff, do so only after the remote send to the shared branch succeeds ([Practices > GIT > Shared Synchronization State Machine > Resolve the upstream]); a failed send keeps this session active and explains that the other clone cannot receive the checkpoint. The other computer must need nothing beyond `^resume`: fix here, before sending, anything that would otherwise need a step there. What no Agent can fix, such as an installed tool or a login, is reported by `^resume` there as infrastructure to re-establish. A full-folder handoff may shut down after the local save because User will copy that folder directly. Otherwise keep the current session active. STOP.
