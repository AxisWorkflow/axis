# ^split
> **Purpose:** Turn a project subfolder into an independent Axis Subproject with relevant parent history.

1. Main Agent only. Load [Practices > Splitting]. Resolve the target subfolder from User's request; ask only if unspecified or ambiguous. This creates a Subproject in place; it does not move the folder elsewhere.
2. Preview the folder, existing content, project scope, parent history and repository arrangement. Reject an existing or incomplete child, unsafe paths or live work touching the target. Review a verified Axis release template before installation; never clone the parent's live control state.
3. Crawl all live and archived parent record families, including archived imports. Read the records that may relate to the new project, follow their dependencies and record a reasoned copy/support/skip decision for every record. Semantic relevance requires Main review; a filename or keyword match alone is insufficient. Preserve copied history, identifiers and provenance; keep parent originals unchanged.
4. Prepare the complete child in disposable staging with its existing content, verified Axis installation, fresh project identity, scoped Project/Plan, relevant history and rebuilt indexes. Present one concrete plan covering installation, history selection, active-work ownership, Git consequences and rollback. Existing explicit authorization covers its named scope; ask only for missing consequential choices under [Rules > Permissions].
5. Follow [Practices > Splitting] through verified publication of the complete staged folder, first-boot readiness, parent checkpoint and completion receipts. Write the parent completion Log Event with the child path, provenance receipt, verification and active-work ownership; keep the child setup receipt as specified in the Practice. No parent Main writes into the child after the split completes. Report the new Subproject's location and how to open it. User may later move it elsewhere; no move, remote or provider launch is implied. STOP.
