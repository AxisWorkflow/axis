# Secrets
> **Purpose:** The one sanctioned home for credentials, and the reference-first ladder for using them.


- `_Axis/Secrets/` is the only sanctioned home for secrets: API keys, tokens, credentials, and anything else User wants kept out of every record. Plaintext contents are excluded from Git by the shipped `.gitignore`. When User enables [Practices > GIT > Encrypted Secrets Transport], the only additional tracked entries permitted there are `.recipient` (public configuration) and `.capsule.age` (verified ciphertext); `.binding` remains local and ignored.
- The reference-first ladder governs use: (1) prefer the host's native secret store (keychain, credential system, environment) where one exists; (2) otherwise USE BY REFERENCE - pass the secret's PATH to shell commands (`$(cat _Axis/Secrets/x.key)`) so the value transits the shell, never your context; never echo or print a secret file, and redirect tool output that might reflect it (requires `host-shell`); (3) read a value INTO context only on explicit User instruction naming the secret - then tell User the value now sits in this transcript and transits the model provider, and never relay it to any Subagent or External Agent.
- Local Subagents and External Agents never handle secrets or secret paths - no exceptions.
- A project folder synced to cloud storage syncs its secrets too (`host-cloud-sync` detects this) - warn once at Session Start when both conditions hold.
- Read `_Axis/Secrets/` only when a task requires a credential or User directs you there. `_Axis/Secrets/` is never part of a content sweep, index, Wiki build, Snapshot, or Starting Context. Two metadata-only exceptions exist: [Practices > Portability > Infrastructure Inventory] may perform one output-suppressed existence predicate for plaintext credential material, excluding `.gitkeep`, `.recipient`, `.capsule.age`, and `.binding`; and [Practices > GIT > Encrypted Secrets Transport] may run the shipped helper, which reads content only through local shell streams and emits status tokens without names or values. Neither exception loads a name/value into model context.
- Never copy, quote, print, or log a value from `_Axis/Secrets/` - not into chat, and not into any file (Tasks, Follow-Ups, Logs, Notes, Snapshots, Wiki, deliverables, Dashboard). Refer to secrets by filename instead (e.g., "the key in `_Axis/Secrets/keys.md`").
- Never stage any plaintext `_Axis/Secrets/` path, even for a private remote. Never substitute Base64, a passworded ZIP, or home-grown encryption for the optional capsule. The private capsule identity stays outside the project and is used only by path; never read, print, copy into a record, or relay it to another Agent.
- If you spot a secret OUTSIDE `_Axis/Secrets/`, warn User and offer to move it there; if it was ever committed or published, also advise User to rotate it.
- `_Axis/Secrets/` is hygiene, not a vault: any Agent or process running with User's file permissions can still read it. For high-value credentials, advise User to prefer the host's keychain, config, or environment variables when the host supports them.
- The encrypted capsule protects the repository copy, not plaintext on an authorized endpoint. A copied private identity can decrypt historical capsules even after repository access is revoked; exposure requires identity replacement and rotation of the represented service credentials.
